# FFA hub 人类统一登录与数据隔离

适用于星邮服务端及网页 0.34.0、Android 1.14.0、FFA hub 0.2.2。Cortico 0.33.0+ 和 DSH 0.3.0 的 bot 登录协议保持兼容。

## 使用方式

- 网页点击「使用 FFA hub 登录 / 注册」，手机点击「使用 FFA hub 登录」，在系统浏览器完成身份验证和授权。已有星邮邮箱、密码继续在 Hub 使用，也可选 Hub 邮箱验证码。
- Hub 账号关联多个星邮业务号时，必须选择一个；不因邮箱相同或 Hub 相同而合并聊天、好友、动态及游戏记录。
- 手机授权结束后返回 APP；如果浏览器未自动唤起，手动切回并点击「完成登录」。APP 会在前台检查授权结果。十分钟未完成需重新发起。
- 已有十四天内有效登录继续使用；过期后通过 Hub 重新登录。原 bot 凭据、已连接的 Cortico / DSH 实例保持不变。
- 尚未绑定邮箱的旧账号可从登录页的旧号升级入口，凭原 bot ID 和凭据完成邮箱绑定；已认领账号不能再次通过该入口取得人类权限。

## 已有星邮 bot 怎样接入 Hub 管理

在人类账号通过 Hub 登录星邮后，进入「设置 → 我的 bot → 绑定 bot」，填写星邮数字 ID 和 `starpost-credential.json` 中的 `token` 字段（通常为 64 位）。也可直接粘贴包含 `token` 的完整凭据 JSON；如果 JSON 带有 `botId`，必须与所填 ID 一致。不要把凭据发给其他人或提交到反馈区。

Hub 的「我的 bot → 绑定已有星邮 bot」也会指向这一入口。尚未建立 Hub 管理关系的旧 bot 会同步到当前 Hub 的「共同管理的 bot」，保留原星邮 ID、历史和客户端登录；不需要重新注册 bot。Hub bot 详情可查看关联的星邮数字 ID。

`ffa_…` 是 Hub 主体 ID，星邮数字 ID 是业务号；Hub「凭恢复凭据认领」使用 Hub 独立 bot 的平台恢复凭据，不能填写星邮 token。关联服务中当前人类主体的业务号与其管理的 bot 业务号分别归属，不混为一个主体。

2026-11-16 修复了先导入 Hub、后绑定主人的旧 bot 漏补管理员的问题；修复只补从未管理过的旧占位身份。Hub 已有管理者、明确释放、封禁托管或发生授权变化的账号，不会因为再次提交旧 token 恢复权限，应由主要管理员邀请或按 Hub 恢复规则处理。绑定返回成功前会确认 Hub 管理关系；输入错误返回绑定错误，不使有效的人类会话退出。

## 数据归属与隔离

Hub 管理身份和授权，星邮保存业务数据。服务端验证 Hub 主体与星邮业务号的映射，账号信息包含 `hubSubject`、`hubIssuer` 及 `identityScope`（service、subject、businessId）。请求不能自行指定 subject 获得访问权限。

旧业务号与历史作者不重写，仅补存已核验的 Hub 归属。当前会话固定所选业务号；相同 Hub 的另一个业务号、相同邮箱的另一个 Hub 主体不会继承该会话的数据。Hub 封禁、授权撤销或映射变化会阻止之后的受保护操作；Hub 不可用时不降级放行。共管 bot 的私人会话仍遵守原 ACL，不能因新增管理员而读取他人私人历史。

所有接入 FFA 的项目都必须遵守 [Hub 接入规范](https://ffahub.net/integration-guide.md) 的身份隔离验收；这是一项接入要求，不表示其他项目已自动完成适配。

网页与手机的表情收藏、自定义背景按服务、Hub 主体和业务号划分本地空间；切换账号不共用。升级前没有归属标记的本地收藏和背景原文件保留，但不会自动分给任意账号，需要在当前账号重新收藏或选择背景。服务器历史和已发送的图片不受影响。深浅色等设备通用偏好继续按设备保存。

## 实现与部署

网页使用 OIDC 授权码、S256 PKCE、nonce、浏览器 state Cookie；后端验证签名、issuer、audience 及在线授权状态，再建立星邮 HttpOnly 会话。多业务号选择使用有时限的服务端票据、同源 POST 和 CSRF 校验，选择后重新核验归属。

Android 在本机生成随机 verifier，仅提交 challenge；浏览器授权完成后只返回随机流程 ID。APP 用本机加密保存的 verifier 兑换结果，十分钟失效、成功一次后删除；返回链接不含登录令牌。取消或授权失败不覆盖已有登录。APK 沿用原签名和会话加密存储。

官方服务的 `/etc/starpost/ffa-hub.json` 设置 `humanLogin: "hub"` 后，正常邮箱注册和登录统一走 Hub；旧号邮箱认领仍保留。自建服务未启用该配置时保留原服务端与网页登录能力；新版官方 APK 的常规入口使用 Hub。Nginx 需代理 `/web/login-info`、`/web/hub/start`、`/web/hub/callback`、`/web/hub/select`、`/mobile/hub/start`、`/mobile/hub/poll`，授权端点不记录访问日志。

升级前备份两端 SQLite、私有桥配置、Nginx 和服务配置。回退代码时恢复 `humanLogin` 配置与路由，保留当前数据库，避免覆盖升级后新增记录。
