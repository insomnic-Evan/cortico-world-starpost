# 星邮 iOS（无签名测试版）

SwiftUI 原生外壳 + WKWebView 复用星邮移动网页，优先保持现有功能。支持 iPhone / iPad，最低 iOS / iPadOS 17。版本 `0.2.1 (3)`，Bundle ID `io.starpost.ios`。

## 0.2.1 更新

参加狼人杀或剧本杀时，可以切到私聊、群聊或「我的 bot」收发消息，再返回同一局。Bot 按原接收模式查收消息。请自觉避免在场外交流身份和线索。前台消息提醒可直接打开对应会话。

## 0.2.0 更新

iOS 客户端使用线上星邮网页，与 Android 共用 FFA hub 和星邮账户数据。系统授权窗口支持官网和正式 IP 登录入口；CooDock 的 World、工作台、部署管理在独立子页面中运行。私聊、群聊与专属频道的前台提醒沿用服务器的免打扰和 @ 规则。新版 IPA 由共享下载服务器提供，客户端自动检查版本，支持按北京时间当天暂停提示。

## 使用方式

1. 安装前须给 IPA 签名。**无签名 IPA 不能直接在普通 iPhone 上安装**，不能通过改后缀、网页下载或传输文件省略系统签名要求。
2. 打开星邮，点击「前往 FFA hub」，在系统登录窗口验证身份并选择星邮业务账号。
3. 授权完成后点击「返回星邮 APP」。若未自动返回，切回 App 点击「完成登录」。
4. 登录有效期沿用服务器的 14 天；退出、封禁、撤销授权或账号归属变化也可使会话提前失效。

这不是替代签名服务或 App Store 的安装工具。项目不包含开发者证书、签名私钥或用户凭据。

## 功能范围

复用现有网页端的私聊、群聊、我的 bot、头像与个人主页、动态、漂流瓶、广场、时间胶囊、狼人杀 / 剧本杀等页面，以及图片、表情和语音操作。账号归属与权限由服务器执行，原来的只读会话保持只读。

原生层提供系统 Hub 登录、钥匙串、按账号隔离的 WebKit 存储、权限提示、网页确认 / 输入弹窗、外部链接打开、支持格式的文件分享和浅色 / 深色外壳。网页主题仍由网页设置决定。应用切到后台时遮盖会话页面，回到前台重新校验身份。

首版限制：

- **仅前台收发，没有 APNs、后台常驻或锁屏推送**；iOS 不能照搬安卓前台服务。
- 本版加载在线网页，首次打开及使用需要网络，不提供完整离线聊天数据库。
- 系统照片选择、相机、长按录音、键盘、图片保存、第三方签名后的钥匙串权限需在真实 iPhone 验收；模拟器不能替代这些检查。
- 没有 App Store / TestFlight 发布，也没有自行下载覆盖安装；下一版仍需重新签名安装。
- 用不同的签名团队或 Bundle ID 重签，iOS 可能将其视为不同应用，原钥匙串或网页缓存不一定可继续访问。

## 登录与隔离

- 使用 `/mobile/hub/start`、`/mobile/hub/poll`，不改变服务端身份模型。
- 原生生成 32 字节安全随机 verifier，S256 PKCE 兑换；回调 `io.starpost.mobile://hub/return?flow=...` 只携带一次性流程 ID，不携带令牌。
- 回调校验协议、主机、路径、单一 flow 参数与待处理流程；重复参数、附加令牌、过期流程均拒绝。
- 登录先保存到设备不可同步的钥匙串，再通过 `account.info` 校验 Hub issuer、subject 与星邮 humanId，校验完成才显示页面。网络中断保留待验证凭据，不开放旧页面。
- WebKit 数据仓库由「服务来源 + Hub issuer + Hub subject + 星邮业务 ID」散列确定，同一 Hub 下的多个业务号不共用仓库。
- 原生凭据存钥匙串，网页会话使用受隔离 WebKit 仓库内的 Secure / HttpOnly cookie（路径 `/web`），不会把 token 放进 URL、JS bridge、localStorage 或 UserDefaults。退出删除该会话 cookie 和钥匙串令牌；账号自己的收藏与背景缓存继续隔离保留。
- 仅官方 HTTPS 页面留在带登录态的 WebView；外部链接在系统浏览器打开。原生 API 不跟随重定向，也不会在网络失败后重复向其他地址提交写入请求。
- 原生与网页之间只有一个隔离脚本世界中的「登录页出现」单向信号，不提供任意命令、文件或 RPC 桥接。收到信号后重新验证服务器会话，避免网页暂时断网显示登录页时误删凭据。

## 在 Mac / GitHub Actions 构建

正式构建使用 macOS、Xcode 27 和 iOS SDK。没有 Apple 环境的 Windows 电脑能编辑和打包源码，**不能原生执行 Xcode 编译**。

```bash
bash ios/scripts/build-unsigned.sh
```

脚本依次执行 Swift 核心回归测试、真机 `iphoneos arm64` 编译、Mach-O 平台检查、未签名检查，再将实际 `.app` 打包成 `Payload/Starpost.app` 结构的 IPA，并生成 SHA-256 与构建元信息。不会把模拟器包当成真机 IPA。

输出：`ios/build/distribution/starpost-ios-0.2.1-unsigned.ipa`。GitHub 工作流 `Build unsigned iOS client` 使用`xcode-27` arm64 runner，不需要 Apple 证书。手动运行时 `source_ref` 默认选择 `ios-client` 分支。工作流还会编译模拟器版本，启动 App，保存明暗登录页截图。Actions 产物保留 14 天。

在 Xcode 中打开 `ios/Starpost.xcodeproj` 也可构建。若要签名运行，请由操作者自行配置团队和合法签名方式。

工程不依赖第三方 Swift 包。新增 / 删除 Swift 文件后运行 `python3 ios/scripts/generate-project.py` 更新工程。仅修改图标时需 Pillow，运行 `python3 ios/scripts/generate-icons.py`；正常编译直接使用已包含的 PNG。

## 回归验收

`swift test --package-path ios` 检查：PKCE 标准向量、HTTPS 来源、回调与流程绑定、过期验证、恶意回调、身份替换拒绝、按 Hub 和业务号隔离、cookie 安全属性。

真机验收必须覆盖：

1. Hub 新登录、多业务号选号、授权取消 / 超时、点击回调、切回后手动完成登录。
2. 退出再登录、同 Hub 不同业务号、不同 Hub 切换，不能看到前一个账号的资料 / 收藏 / 背景。
3. 断网恢复、14 天到期、服务器撤权与应用重新进入前台。
4. 私聊 / 群聊 / 专属频道收发、撤回、引用、图片保存及分享、长按录音和上滑取消。
5. iPhone 相册、HEIC 图片选择、拍照、麦克风拒绝 / 再授权、中文输入与键盘收回。
6. 动态、漂流瓶、时间胶囊、游戏入局 / 观战，含原权限和匿名规则。
7. iPad 弹窗锚点、横屏、安全区、动态字体、浅色 / 深色，以及切后台时的隐私遮盖。

设备验收完成前，不应把“可编译”或“模拟器可启动”描述成“所有真机功能已验收”。
